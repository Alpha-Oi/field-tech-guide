# Словарь проекта

Слова, которыми проект называет свои части. Их стоит использовать одинаково в коде, тестах, документах и сообщениях коммитов. Почему проект устроен так, объясняют [записи решений](docs/adr/README.md); что где лежит, показывает [architecture.md](docs/architecture.md).

## Гайд

- **Этап** — раздел гайда, один файл `guide/content/NN-имя.json` с блоком `stage` (`id` вида `s1`, `s4b`; «этап 4а» в тексте). Порядок этапов задаёт номер в имени файла.
- **Шаг** — единица внутри этапа с неизменным `id` вида `s1-01`: по нему страница хранит прогресс. Состоит из заголовка, короткого текста, пунктов, готовых сообщений, ссылок, совета и строки «Готово, когда …».
- **Действие, покупка, знание** — три вида шага (`kind`: `do`, `buy`, `know`). У действия кнопка «Сделано», у покупки «Куплено», у знания «Прочитал». Условные случаи (например, отмены) — знания: их читают, а не выполняют.
- **«Готово, когда …»** — поле `proof`: что должно появиться, когда шаг действительно сделан (сообщение диспетчера, учётная запись, скрин). Обязательно для действий и покупок; делает шаг проверяемым.
- **«Дополнительно»** — шаги с `optional: true`. Не входят в «Готов к первой заявке».
- **«Готов к первой заявке»** — подсказка вверху страницы: пока не отмечены обязательные шаги этапов 1–3, она считает, сколько осталось. Страница не блокируется, а лишь подсказывает.

## Данные компании

- **Переменная профиля** — метка `{{имя}}` в тексте на месте всего, что принадлежит компании (название приложения, ник, ссылка, ориентир цены). Подставляется при сборке.
- **Профиль** — JSON `{name, vars}` со значениями переменных. Демо — `guide/profiles/demo.json`; настоящий — `private/profile.json`, в git его нет. Смысл переменных — в `guide/profiles/VARS.md`.
- **Рантайм-токен** — метки `{{order}}` и `{{phone}}`: при сборке не трогаются, страница подставляет в них номер заявки и телефон из полей «Памятки на заявку». В `guide.md` это `[НОМЕР ЗАЯВКИ]` и `[ТВОЙ ТЕЛЕФОН С 8]`.
- **Заглушка** — видимая запись в квадратных скобках (`[впиши: …]`, `[прайс выдаёт техдир]`) на месте факта, которого нет. Выдуманное значение вместо неё ставить нельзя.
- **Прайс** — отдельный JSON со списком услуг и таблицами цен. Переменных в нём нет. Демо — `guide/profiles/demo-pricelist.json`, настоящий — `private/pricelist.json`.
- **Позиция** — одна строка прайса (`items[]`) с номером, группой, названием и видом цены: `fixed` (точная), `from` («от N»), `ask` («уточнять»), `na` («недоступно», добавить в акт нельзя).
- **Матрица** — таблица «модель × услуга» в прайсе (`matrices[]`): строки — модели, столбцы — услуги, в ячейке цена.
- **Ячейка-объект** — ячейка матрицы вида `{"hint": "…", "from": N}`: цену вводит мастер, `hint` подсказывает формулу, `from` — нижний ориентир, ниже которого страница только предупреждает.

## Заявка и документы

- **Памятка на заявку** — кнопка внизу экрана и панель: цепочка «когда → что нажать в приложении → что написать в чат», два поля (номер заявки, телефон; нигде не сохраняются) и формы отчётов.
- **«Чистыми»** — число для отчёта и поля «Сумма» в приложении: «Всего» (всё, что заплатил клиент) минус «Запчасти» (по чекам). Формы отчётов описаны данными в `90-cheatsheet.json`.
- **Акт** — БСО, акт выполненных работ: документ, который остаётся у клиента. Панель «Прайс и акт» выбирает оказанные услуги, считает «К оплате» и даёт текст для бланка; сам бланк заполняют от руки на бумаге.
- **«Мод»** — забор техники у клиента на длительный ремонт вместо ремонта на месте. У него свои правила (предоплата, срок, число одновременных забранных устройств; значения — в тексте этапа 4а и переменной `mod_prepayment`) и два отчёта: о заборе и о закрытии (`mod_pickup`, `mod_close`).

## Сборка и проверка

- **Записка техдиру** — `for-techdir.md`: как внедрить гайд, чтобы мастера его выполняли. Шаблон — `guide/docs/for-techdir.md`, значения подставляет профиль.
- **Чистая сборка** — сборка демо из свежего клона, без `private/` и без послабляющих флагов: демо-профиль, демо-прайс, строгая проверка переменных. Её запускают CI и Pages; пока она не проходит, публичный репозиторий сломан. Не путать с настоящей сборкой (`--profile private/profile.json`).
- **Маркер** — слово из локального `private/markers.txt`, которого не должно быть ни в одном публичном файле. Не путать с метками шаблона (`<!--GUIDE_DATA-->`, `logic:start`).
- **Запрещённый список** — локальный `private/forbidden.txt`: значения переменных, числа и шаблоны текста, которых нет в демо и публичных файлах. Без него соответствующие тесты пропускаются с пометкой.
- **Логика страницы** — чистые функции шаблона между `/* logic:start */` и `/* logic:end */`; их проверяют через `node`.
- **Витрина** — то, что видит посетитель репозитория: README со снимками и схемами, график «Шагов по этапам», документы проекта. Всё сделано на демо-данных.
