# Как раздать гайд мастерам

Сначала соберите гайд из профиля и прайса компании, затем выберите способ раздачи. Гайд не требует сервера: это обычные файлы. Что где хранится и что нельзя публиковать — в [privacy.md](privacy.md).

## 1. Собрать гайд

**Демо** с вымышленными данными собирается одной командой:

```bash
python guide/build.py
```

**Настоящий гайд** собирается из вашего профиля и прайса. Они лежат в папке `private/`, которая в git не попадает.

Bash (Linux, macOS, Git Bash):

```bash
mkdir -p private
cp guide/profiles/demo.json private/profile.json
```

PowerShell (Windows):

```powershell
New-Item -ItemType Directory -Force private | Out-Null
Copy-Item guide/profiles/demo.json private/profile.json
```

1. Замените значения в `private/profile.json` на свои. Смысл каждой переменной и пример — в [guide/profiles/VARS.md](../guide/profiles/VARS.md); актуальный список печатает `python guide/build.py --list-vars`. Ссылки обязаны начинаться с `https://`.
2. Положите свой прайс в `private/pricelist.json`; формат — в [pricelist.md](pricelist.md). Если своего прайса нет, добавляйте к командам флаг `--no-pricelist`: иначе в гайд попадёт демо-прайс с вымышленными услугами, а флаг `--pricelist` в командах ниже уберите.
3. Проверьте и соберите:

```bash
python guide/build.py --check --profile private/profile.json --pricelist private/pricelist.json
python guide/build.py --profile private/profile.json --pricelist private/pricelist.json --out private/dist
```

```powershell
python guide/build.py --check --profile private/profile.json --pricelist private/pricelist.json
python guide/build.py --profile private/profile.json --pricelist private/pricelist.json --out private/dist
```

В папке `private/dist` появятся три файла:

- `index.html` — страница-гайд для телефона: один файл, стили и скрипт внутри, работает без интернета после открытия;
- `guide.md` — тот же гайд текстом: чтобы закрепить в чате или напечатать;
- `for-techdir.md` — записка для техдира: как внедрить гайд, чтобы мастера его выполняли.

Перед раздачей найдите в `index.html` и `guide.md` оставшиеся заглушки в квадратных скобках вида `[впиши: …]`: значит, в профиле остались неподставленные значения.

## 2. Выбрать способ раздачи

Настоящий гайд содержит данные компании. Раздавайте его только тем, кому он предназначен: не выкладывайте в открытый доступ и не добавляйте в публичный репозиторий.

**Отдельный файл.** Самый простой способ: отправьте мастеру `index.html`, он сохранит файл на телефон и откроет его в браузере. Дальше нужен только сам файл, интернет не нужен. Если файл открылся там, где браузер не даёт хранить данные, страница скажет об этом одной строкой и не запомнит отметки: тогда сохраните файл на телефон и откройте его в обычном браузере.

**Ссылка.** Разместите `index.html` на любом статическом хостинге по вашему выбору, в закрытом для посторонних месте, и отправьте мастерам ссылку. Отметки пройденных шагов хранятся в браузере и привязаны к адресу страницы, с которого она открыта.

**GitHub Pages.** В репозитории настроен `.github/workflows/pages.yml`: при push в `main` он проверяет проект, собирает демо командой `python guide/build.py --out dist` и публикует его на GitHub Pages. Включить публикацию нужно один раз: в настройках репозитория, раздел Pages, источник сборки (Source) — GitHub Actions. Адрес страницы будет вида `https://<аккаунт>.github.io/<репозиторий>/`. GitHub Pages публикует только демо с нейтральным профилем: настоящий гайд собирается локально и сюда не попадает. Pages подходит, чтобы показать, как выглядит гайд, но не для раздачи гайда с данными компании.

**Пересылка в мессенджер.** Отправьте файлы как документы:

- `index.html` — мастерам;
- `guide.md` — как текст для закрепления в чате мастеров;
- `for-techdir.md` — техдиру.

Мессенджеры иногда открывают HTML-файл во встроенном просмотре: если страница не запоминает отметки, сохраните файл и откройте его в обычном браузере.

## 3. Как обновлять

1. Поправьте тексты в `guide/content`, значения в `private/profile.json` или прайс в `private/pricelist.json`.
2. Запустите проверку и пересоберите гайд (команды выше).
3. Разошлите новый `index.html` тем же способом. Что изменилось, записывайте в `CHANGELOG.md`.

Прогресс мастера хранится по `id` шагов, поэтому не меняйте `id` существующих шагов: иначе отметки этих шагов пропадут. Новые шаги получают новые `id`. Отметки привязаны к браузеру и к адресу страницы: если мастер откроет новую версию с другого адреса или в другом браузере, они не перенесутся. Это нормально, начать заново можно кнопкой «Начать заново».

Как вносить правки в тексты — в [CONTRIBUTING.md](../CONTRIBUTING.md).
