# ADR 0006. График «Шагов по этапам» строится из контента

- **Статус:** принято
- **Дата:** 2026-10-27

## Контекст

В README есть график «Шагов по этапам». Нарисованный руками, он устаревает незаметно: тексты правятся, шаг добавили или перенесли, а картинка остаётся прежней. Нужен график, обновить который нельзя забыть, и чтобы для этого не требовалось ни зависимостей, ни внешних сервисов.

## Решение

- **Генератор** `tools/make_charts.py` (стандартная библиотека) читает `guide/content/*.json`. Файлы без блока `stage`, например памятку, он пропускает. По каждому этапу считает обязательные шаги и шаги с `optional: true` и пишет `docs/img/steps-by-stage.svg`: горизонтальный столбчатый график, где дополнительные шаги выделены другим цветом.
- **Результат детерминирован.** Одинаковый контент даёт побайтно одинаковый файл: фиксированные размеры и цвета, окончания строк LF, никаких дат. Цвета заданы явно на светлой подложке, потому что GitHub показывает SVG как обычную картинку и не видит тем страницы. У рисунка есть `role="img"`, заголовок и описание.
- **Проверка** `python tools/make_charts.py --check` ничего не пишет и завершается кодом 1, если файла нет или он не совпал с тем, что получится из контента; перевод строк CRLF на сравнение не влияет. Команда входит в проверку целиком и запускается в обоих workflow (`ci.yml` и `pages.yml`). Тесты `test_charts.py` проверяют и сам генератор, и то, что файл в репозитории актуален.
- **Обновление.** После правки контента запускают `python tools/make_charts.py` и фиксируют SVG вместе с правкой. Руками файл не правят: проверка заметит расхождение.

## Последствия

- Правка контента с устаревшим графиком не пройдёт CI. Цена: лишний изменённый файл при каждом изменении числа шагов.
- График не читает профиль, прайс и `private/`, только число шагов, поэтому данных компании в нём нет.
- Генератор знает формат контента (`stage`, `steps`, `optional`) и читает файлы сам, не через `guide/build.py`. При смене схемы контента его правят вместе со сборкой.
- Возможности ограничены ручной генерацией SVG: нет интерактивности, а ширина подписей считается приближённо, поэтому в разных системных шрифтах они выглядят чуть по-разному.
- Остальные схемы в README (поток данных, карта этапов, жизненный цикл заявки) написаны в Mermaid; соответствие карты этапов контенту тоже проверяет тест.

## Рассмотренные альтернативы

1. **Нарисовать в редакторе и положить PNG.** Устаревает без предупреждения и не проверяется. Отклонено.
2. **Внешняя библиотека построения графиков или онлайн-сервис картинок.** Библиотека нарушает правило нулевых зависимостей ([ADR 0002](0002-одна-страница-без-зависимостей.md)), а ссылка на сервис делает README зависимым от чужого сайта.
3. **Диаграмма Mermaid с числами, вписанными вручную.** Те же числа пришлось бы хранить в README и сверять с контентом разбором разметки; у генератора один источник данных.
