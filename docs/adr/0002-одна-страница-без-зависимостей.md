# ADR 0002. Страница одним файлом, без внешних подключений и зависимостей

- **Статус:** принято
- **Дата:** 2026-10-27

## Контекст

Мастер читает гайд с телефона, на ходу, нередко без устойчивого интернета, а файл ему пересылают в мессенджере. Серверов, учётных записей и расходов у проекта нет и не должно быть. При этом страница считает отчёты и акт, поэтому её логика должна проверяться автоматически, а не только глазами.

## Решение

- **Один файл.** `index.html` содержит стили, разметку и скрипт. Данные лежат во встроенном блоке `<script type="application/json" id="guide-data">`: `render_html` вставляет его вместо маркера `<!--GUIDE_DATA-->` и экранирует последовательности `</` и `<!--`.
- **Никаких внешних подключений.** Нет CDN, внешних шрифтов, аналитики, картинок по ссылкам, внешних скриптов и сетевых вызовов. Тест проверяет, что в шаблоне нет адресов `http://` и `https://`.
- **Данные не становятся HTML.** В DOM они попадают через `textContent` и `createElement`; разметка `**жирный**` разбирается собственным разбором в узлы; кликабельны только ссылки `https://`.
- **Python — только стандартная библиотека** (3.10 и новее), без `pip`. Страница — чистые HTML, CSS и JS без сборщика и `npm`.
- **Логика отдельно от DOM.** Чистые функции (разбор разметки, подстановка токенов, расчёт отчёта, готовность, расчёт акта) лежат в шаблоне между строками `/* logic:start */` и `/* logic:end */`. Python-тест вырезает этот блок и запускает его через `node`. Без `node` локально такие тесты пропускаются с пометкой, а при `REQUIRE_NODE=1` (так в CI) падают, чтобы страница не осталась непроверенной.

## Последствия

- Раздать гайд можно любым способом: файлом, ссылкой, через мессенджер. После открытия интернет не нужен.
- Устройство страницы и расчётов проверяется без браузера. Вёрстка и поведение DOM автоматически не проверяются: внешний вид смотрят глазами (это в дорожной карте README).
- CI обязан ставить `node`; разработчику локально он необязателен.
- Шаблон — один длинный файл без типов и сборщика. Библиотеку (графики, компоненты) не подключить, приходится писать небольшие функции самим.
- Ограничения распространяются и на инструменты: проверка утечек и график ([ADR 0003](0003-защита-от-утечки.md), [ADR 0006](0006-генерация-графика.md)) тоже написаны на стандартной библиотеке.

## Рассмотренные альтернативы

1. **Фреймворк с цепочкой сборки на `npm`.** Дают готовые компоненты, но тянут зависимости, обновления и сборщик ради одной страницы без серверного состояния. Отклонено.
2. **Несколько файлов (HTML, CSS, JS, JSON).** Удобнее править, но при пересылке в мессенджере и открытии из хранилища телефона относительные пути ломаются. Единый файл надёжнее.
3. **Серверное приложение или PWA с service worker.** Нужны хостинг и HTTPS, а при открытии файла с диска service worker не работает. Это лишняя инфраструктура для задачи «прочитать и отметить».
